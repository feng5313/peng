
# 项目需求描述

## 1. UI模块

- 1.1 bin/fly（cli主程序入口） bin/msg(cli消息管理) bin/task（cli事务管理）
- 1.2 bin/fly service后台服务模式，开启消息监控，不主动创建新消息，低消耗值守。
- 1.3 bin/fly 消息，非交互模式，处理命令行消息后退出
- 1.4 bin/fly 交互模式，可连续输入消息处理
- 1.5 bin/fly 调用消息管理模块创建消息获取回复的消息并显示。调用进程处理模块获取处理当前消息的进程列表（进程调用链链首为当前消息链链首消息），获取输入输出管道显示信息
- 1.6 bin/fly 交互模式下，所有输入默认为回复上一个输入消息（如果没有则为新消息），按同一消息回复链处理
- 1.7 bin/fly 用内置命令/new或/clear清除上下文强制开始新消息处理流程，此时不主动中断、取消或暂停前一个消息链处理，但不再显示前一个消息链的处理进程输出管道，而是显示新处理流程的进程输出管道。
- 1.8 bin/fly **用内置命令/reply id 消息 来回复已有消息链**，如果id不属于当前消息链，则开始处理id回复的消息链。此时不主动中断、取消或暂停前一个消息链处理，但不再显示前一个消息链的处理进程输出管道，而是显示id回复链的进程输出管道。
- 1.9 bin/fly 命令行prompt消息（如果不为空）默认为新消息，除非有-r --reply参数指定回复消息ID
- 1.10 bin/fly 未退出时，快速按2次Esc，或者按1次Ctrl+C可以暂停当前消息链处理（可继续输入消息恢复处理），连续再按1次Ctrl+C这取消当前消息链处理（加新标记'取消'，黄色高亮）并退出程序。
- 1.11 bin/fly 加**命令行参数-c --continue继续开始处理最近的调用链首消息**。此时命令行prompt消息作为回复消息加入回复链。加内置命令/continue实现同样功能（只有命令行无prompt消息且未输入新消息时有效，否则回复当前消息链“继续”）。
- 1.12 bin/task 事务cli管理接口：获取消息链上下文/事务树/调用链/进程信息/事务属性/状态/当前执行步骤/当前上下文/开始时间/心跳/调整优先级/暂停/取消/重启（从步骤1开始）/恢复（从暂停和意外中断的步骤恢复上下文开始）
- 1.13 bin/task 无参数则显示正在处理中的事务树的全部状态和信息（树状结构）
- 1.14 bin/msg 所有消息的cli处理接口
- 1.15 bin/msg 支持根据--task 消息ID调用bin/task查询事务/事务树，根据--pause/cancel 消息ID暂停/取消事务/事务树，根据--up/down 消息ID提高/降低事务/事务树优先级，根据参数--processing查询所有处理中的消息状态和对应事务树详细信息；根据--timeout 秒 消息内容 设置新消息处理超时时间，默认为0（永不超时）；根据--reply ID --timeout 秒 修改指定消息的超时
- 1.16 bin/fly 加内置命令/msg调用bin/msg传递所有参数获取打印相应信息。加内置命令/task调用命令bin/task传递所有参数获取打印相应信息。
- 1.17 bin/fly 默认支持非交互/交互模式rich显示UI界面。
- 1.18 bin/fly 也支持Textual TUI交互模式UI界面，尚未开始正式设计开发，但需保持现有功能不被破坏

## 2. 程序流程

- 2.1 bin/fly启动**UI循环（交互模式），消息监控循环，心跳监测循环。除了这三个循环，不应该存在其他无限循环**。
- 2.2 bin/fly创建新消息时，调用消息管理模块自动开始处理。消息/事务的属性数据带并行锁，防止并发冲突。
- 2.3 调用链传递：调用者（fly或者inbox_monitor）-> 消息ID -> 事务ID -> 子事务ID -> 进程ID。每一级调用下一级时，传入整个调用链加上自己。调用链在每一级的数据里持久化。调用链上每一级理论上都可以获取所有信息。
- 2.4 消息暂停机制：bin/msg改变消息状态为暂停，心跳监测循环负责检查暂停的消息是否带有活跃的事务树，如果有则递归暂停（先处理最底层子事务的当前步骤的进程）。bin/fly中发起暂停则立即检查暂停的消息是否带有活跃的事务树，如果有则递归暂停。然后更新消息状态为暂停。
- 2.5 调用链每一级更新自己的心跳同时通过心跳回调更新上级心跳。 子进程 -> 进程 -> 子事务 -> ... -> 子事务 -> 事务 -> 消息
- 2.6 消息监控循环每13秒（可配置）检查是否有bin/msg创建的新消息，有则调用消息管理模块自动开始处理。

## 3. 心跳机制 src/peng/utils/heartbeat_monitor.py

- 3.1 心跳为最后活跃/更新的时间。消息和事务的心跳持久化在数据中。
- 3.2 心跳监测每1秒（可配置）遍历数据库内所有消息、事务、进程
  - 3.2.1 更新调用链上级的心跳：如果当前心跳比上级新，则更新上级。
  - 3.2.2 如果time.time() - x.start_time > x.timeout，则判断x为超时，设置状态为超时。如果事务树根状态为超时，把消息状态设为超时失败，回复消息 - 发送事务信息（当前步骤等）。
  - 3.2.3 如果事务状态为处理中，但属性中的当前进程ID失效（非0且查无此进程），则判断为进程异常中断，此时应该找到事务树根事务（调用链第一个事务）调用事务管理模块中断处理接口（传递参数根事务ID，进程ID）处理中断。
  - 3.2.4 如果事务管理模块的中断处理接口返回处理中，表示事务已恢复处理；如果返回中断，则更新消息状态为中断。
  - 3.2.5 如果消息状态为处理中，但属性中的事务ID状态为已验收/暂停/中断/失败，则同步事务状态给消息。并整理事务验收标准json文档（如果存在）为简洁文本回复消息报告新状态。
  - 3.2.6 如果事务树状态为已验收，调用链中消息必然为处理中（否则报错消息状态异常），则更新消息状态为已完成，回复消息 - 把事务中的事务验收标准json文档整理成markdown发送（无需大模型参与）。归档事务和消息。
  - 3.2.7 如果消息状态为暂停而对应事务部未暂停（msg暂停的消息只负责设置消息状态不实际暂停事务），调用事务管理模块的暂停接口处理。bin/fly交互界面暂停的消息会立刻执行调用事务暂停接口处理。
  - 3.2.8 归档超过7天（根据心跳算）的暂停/中断/失败消息和事务
  - 3.2.9 归档是独立标记，不是状态的一部分。归档的事务维持归档前状态。归档的消息/事务可被search搜索到，finished列出，可以通过ID获取，不能被msg all/inbox等其他方式列出。

## 4. 消息管理模块 src/peng/core/message

- 4.1 数据库管理消息数据，包括：ID，消息内容，事务ID，消息发送时间，消息接收时间，是否为回复消息，回复消息ID，最新消息上下文，状态（未读/已读/已回复/处理中/验收中/已验收/暂停/中断/已取消/失败）
- 4.2 消息管理模块是处理新消息开始执行事务的唯一接口！bin/fly或者消息监控有新消息 -> 调用消息管理模块处理新消息 -> 如果需要则建立新事务 -> 开始事务处理
- 4.3 消息管理模块处理新消息流程
  - 调用事务管理模块创建事务处理新消息
- 4.4 消息回复链(reply前后所有相关消息)
  - 4.4.1 消息管理模块创建消息时，如果是回复消息按以下方式处理
  - 4.4.2 如果消息链首状态为处理中：把回复链上所有消息整理成完整上下文，传递给回复链链首的消息（第一条非回复消息），并持久化到db数据中。由上下文注入机制应把最新上下文传递给正在运行的大模型处理。无需发起新的事务另外调用大模型。
  - 4.4.3 如果链首消息处理已经结束，应该更新消息完整上下文（包括大模型的处理回复），在提示词中添加消息当前信息（消息状态、事务树，事务树状态），从事务管理模块步骤一开始重启整个消息处理，让大模型决定下一步处理方式。
  - 4.4.4 完整上下文格式：按时间顺序列出消息id，发送者（鹏🐣/master），不含引用的纯粹的本消息内容，控制总长度在4k字节以内（超长则删除最中间的消息直到不超，首尾消息即使超长也必须保留不删）。
  - 4.4.5 实际上处理的所有消息都应该是链首消息。
  - 4.4.6 bin/fly交互模式下，所有输入默认为回复上一个输入消息（如果没有则为新消息），按同一消息回复链处理，除非用内置命令/new或/clear清除上下文取消当前消息链，强制开始新消息处理流程。
  - 4.4.7 bin/fly命令行prompt消息（如果不为空）默认为新消息，除非有-r --reply参数指定回复消息ID
- 4.5 提供获取最新消息上下文的接口，如果不是回复消息则返回自身消息内容，否则返回消息链链首存储最新消息上下文。
- 4.6 编写特殊tool_call帮助大模型随时自动获取最新消息上下文。另外在所有tool_call中都加判断，每当总上下文增加超过30k，就需要加入当前最新消息上下文，强化大模型对事务的记忆。
- 4.7 bin/fly交互界面发起消息暂停，则立刻调用事务暂停接口处理，确保事务树尽快暂停。
- 4.8 bin/msg显示消息信息时应显示消息完整上下文。
- 4.9 所有消息记录调用链，内容为fly或msg，调用事务时传递给事务作为事务调用链的链首，事务调用进程管理模块时再传递给事务

## 5. 事务管理模块 src/peng/core/task

- 5.1 数据库管理事务数据
- 5.2 事务数据内容包括：ID，父事务ID，事务描述，事务工作目录，当前进程ID（无进程则为0），事务开始时间，超时时间，当前步骤，子事务列表，事务优先级，事务验收标准json文档，事务分析报告标准json文档，状态（未开始/处理中/验收中/已验收/暂停/中断/已取消/失败），事务的git worktree、git 分支信息，是否使用父事务的git worktree。
- 5.3 事务执行的git隔离环境设置
  - 5.3.1 可以为无隔离（事务工作目录/继承父事务环境）、仅分支、worktree、完整git克隆
  - 5.3.2 由大模型根据事务信息智能判断
- 5.4 制定事务管理模块可以识别处理的标准json文档，让大模型智能填写内容
  - 5.4.1 标准json文档的格式在代码中定义，需要时在临时目录生成，然后在提示词里加上生成的文档路径，传给大模型，让大模型填写，禁止大模型改变文档格式。
  - 5.4.2 事务验收标准json文档，包含验收条目确认表格（checklist），后继优化建议。对于修改代码、数据、配置的事务，必须真实部署/运行项目，真实实现项目功能。例如本项目需调用“bin/fly 生成python脚本获取天气预报并打印。”（参考tests/test_fly_weather.py）
  - 5.4.3 子事务标准json文档，子事务列表，如果子事务有自己的子事务表则间接形成树状结构，大模型把子事务描述添加到子事务列表，事务管理模块负责创建子事务并在子事务列表中加入子事务ID。
  - 5.4.4 事务执行专家指导提示词json文档，纯文本形式{prompt:str}
  - 5.4.5 事务分析报告标准json文档， 需包含{子事务标准json文档路径，隔离环境设置，事务总时间，事务计划markdown文档路径，事务执行专家指导提示词json文档路径，事务验收标准json文档路径}
  - 5.4.6 大模型填写后的标准json文档，应该持久化到事务数据库中
- 5.5 事务管理模块负责调用大模型处理消息生成事务分拆子事务处理事务验收回复消息：
  - 5.5.1 **事务分析**，调用进程管理模块开启进程调用大模型（需制定事务分析专用提示词 - 在config/prompts.json配置，添加调用链上消息的最新消息上下文）进行事务分析
    - 5.5.1.1 分析事务信息
      - 判断是否简单事务，如果是，直接调用消息处理tool_call回复信息，设置消息状态为已回复，跳过后继步骤。如果不是简单事务，按下面流程处理。
    - 5.5.1.2 判断是否需要建立分支，隔离环境，隔离环境方式（git worktree或者完整clone）
    - 5.5.1.3 确定优先级，预估事务总时间（事务超时时间）
    - 5.5.1.5 大模型根据事务信息，选择合适的专业领域专家执行事务。
    - 5.5.1.6 生成事务计划书进度跟踪表文档并随时跟进更新。
    - 5.5.1.7 决定是否分拆子事务，为子事务更合适的提示词，用tool_call生成子事务，合理分配资源，监控子事务执行，合并子事务成果，合并测试验收。
    - 5.5.10 **事务结束**更新事务状态为已完成/已验收，回复消息。
    - 5.5.10 监控事务输出（OutputManager），疑似中断（20秒可配置的超时时间内无输出和工具调用）的事务要主动恢复
- 5.6 事务执行前后更新事务状态（处理中/验收中/已验收/暂停/中断/失败）、当前上下文。如果调用链上级是消息，更新消息状态。
- 5.8 大模型运行过程中调用tool_call时跟进注入机制强制添加调用链上消息的最新消息上下文。
- 5.11 暂停事务/消息的接口（webui调用），包括bin/msg，bin/task的cli接口。暂停方式为大模型调用tool_call/skills/hooks时保存关键上下文到事务数据中，然后主动等待恢复信号。更新状态为暂停，递归调用子事务暂停接口。回复暂停事务的方式是发送恢复信号。暂停/恢复功能只在服务器持续正常运行时有效，如果暂停的事务在服务器关闭后仍未恢复，要在下一轮服务运行时变更状态为中断，只能通过保存的关键上下文重启事务而不能原样恢复。如果caller是消息，更新消息状态为暂停。
- 5.12 事务意外中断处理的接口（由心跳监控调用），需递归查询事务树中所有子事务是否都中断（状态为中断或者进程ID不为0且失效），如果事务未超时且一半子事务未中断，则重启所有中断的子事务执行并返回状态处理中，否则杀死所有未中断子事务的当前进程，事务树中事务全部状态设置为中断，返回状态中断。
- 5.13 事务调用进程管理模块开启进程时，传入调用链：调用者（bin/fly或者消息监控）-> 消息ID -> 事务ID -> 子事务ID

## 6. 进程管理模块 src/peng/core/process

- 6.1 进程管理模块被调用创建进程时返回进程信息（ID/PID/父进程链/调用链/进程属性/状态/开始时间/心跳的接口，调整优先级的接口，杀进程的接口，还要包括输入输出管道接口以便其他模块输入进程或获取输出）。
- 6.2 进程属性包括：
  - 6.2.1 区分独立进程和子进程，独立进程不会被父进程杀死，子进程跟随父进程杀死
  - 6.2.2 优先级，包含执行先后优先级（进程数量到设置上限时使用）和CPU占用优先级
  - 6.2.3 子进程列表
  - 6.2.4 超时时间和超时回调接口
  - 6.2.5 事务结束回调接口。进程管理模块负责更新调用链上各级的心跳，更新心跳的接口由调用者一级一级传入。进程管理模块需监控（但不截断）进程的stdout/stderr/文件/网络等操作，有操作时更新心跳。事务超时自动杀死、返回相关信息并调用超时回调（若存在）。事务结束时返回相关信息并调用结束回调（若存在）。

## 9. webui

- bin/fly --service 加参数--webui应该同时启动web ui，默认监听地址：0.0.0.0:6688，可在config中配置是否关闭webui，默认开
- webui形式
  - 最上方标题栏，显示项目信息
  - 左边栏：消息树，显示所有未归档消息链，上新下旧排序；可选择哪个消息链进行回复 - 此时应该同时更新相应消息链对应的进程表输出信息到信息显示框
  - 中间主界面：主体信息显示框，最下方标准大模型输入栏（含弹出式模型选择框，思考开关、思维链长度限制选择条带数字输入，搜索开关，上传文件按钮，发送按钮）
  - 右侧栏：事务树，显示所有未完成事务树，可选择具体子事务，自动展开完整子事务树，更新当前消息链，此时输入的消息都是回复此消息链，信息显示框只显示该**子事务树**内的所有进程输出
  - 最下方状态栏，显示运行状态、系统环境、帮助信息链接等
- 可选黑白主题，默认黑色（模拟黑色终端，支持颜色等转义符）
- 信息显示框默认显示bin/fly --service的终端输出的完整内容（终端和webui同时显示），子事务树被选中时只显示该子事务树的进程输出
- 输入输出完全异步，不卡顿
